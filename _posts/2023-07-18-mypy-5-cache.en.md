# Cache

This post looks a bit more closely, with the same example, at the cache that was covered briefly in [How Mypy Works: #1 Pre-optimization](/en/mypy-1-pre-optimization.html). I included a longer cache JSON than the appendix in #1.

mypy saves the cache as files. If you've used mypy, you probably saw a `.mypy_cache` folder get created when you ran mypy.

mypy saves already-interpreted files as cache to reuse later, and newly interprets files that have no cache or whose cache is invalid. If a module's source or dependencies change, even if there's a cache it's stale, and if the cache is valid it's fresh.
Let's take a look for a moment at the cache of a fresh module in `.mypy_cache`.

```python
from fastapi import FastAPI  
  
app = FastAPI()  
  
  
@app.get("/")  
async def root():  
    return {"message": "Hello World"}  
  
  
@app.get("/hello/{name}")  
async def say_hello(name: str):  
    return {"message": f"Hello {name}"}
```

Below is the content in the cache. There's also content that FastAPI brought in from the code was designated as Gdef, global definition, and it seems like you can see that `app`'s type is `FastAPI`, and content about the function definitions of `root` and `say_hello`. This is mypy saving the interpretation result as a file, so if you're curious how mypy interpreted the file or if you need to debug, looking at this file can be enough.
