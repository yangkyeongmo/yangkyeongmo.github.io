# 캐시

이 글은 [Mypy의 동작 방식: #1 진행 전 최적화]({% post_url 2023-07-18-mypy-1-pre-optimization %})에서 짧게 다룬 캐시를, 같은 예시로 조금 더 자세히 본 것입니다. #1의 부록보다 캐시 JSON을 더 길게 실었습니다.

mypy는 캐시를 파일로 저장합니다. mypy를 사용해보신 분들이라면 mypy를 실행했을 때 `.mypy_cache` 폴더가 생성되는 것을 보셨을것 같습니다.

mypy는 이미 해석된 파일은 캐시로 저장해서 이후에 재사용하고, 캐시가 없거나 유효하지 않은 파일은 새로 해석합니다. 모듈의 소스나 의존성이 바뀌면 캐시가 있어도 stale이고, 캐시가 유효하면 fresh입니다.
`.mypy_cache` 에 들어있는 fresh한 모듈의 캐시를 잠시 들여다보겠습니다.

```python
from fastapi import FastAPI  
  
app = FastAPI()  
  
  
@app.get("/")  
async def root():  
    return {"message": "Hello World"}  
  
  
@app.get("/hello/{name}")  
async def say_hello(name: str):  
    return {"message": f"Hello {name}"}
```

아래는 cache에 들어있는 내용입니다. 코드에서 가져온 FastAPI가 Gdef, global definition 으로 지정되었다는 내용도 있고, `app`의 타입이 `FastAPI` 라는 것이나 `root`, `say_hello`의 함수 정의에 대한 내용도 보이는것 같습니다. 이 내용은 mypy가 해석한 결과를 파일로 저장한 것으로, mypy가 파일을 어떻게 해석했는지 궁금하시거나 디버깅을 해야한다면 이 파일을 들여다보는 것으로도 충분할 수 있습니다.
