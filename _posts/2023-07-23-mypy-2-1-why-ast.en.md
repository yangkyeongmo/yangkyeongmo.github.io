# Python's grammar

## Formal grammar

Formal grammar is a formalized notation used to define a language's syntax.
Formal grammar doesn't explain meaning; it only represents the form of the language.

Formal grammar starts from a "start symbol" and generates the language by applying rewriting rules.
Here, a rewriting rule is a rule that replaces one symbol(s) with other symbol(s).
The process of generating a language by applying these rules is called derivation.

## Context free grammar(CFG)

Context free grammar(CFG) is a form of formal grammar where the left-hand side has a single nonterminal and the right-hand side is unrestricted.

CFG is expressed like this.

```
A -> alpha

A: nonterminal
alpha: a string composed of terminals or nonterminals
```
Here a nonterminal is an alphabet that can be expanded, and a terminal is an alphabet that can no longer be expanded.

### CFG example

For example, the following grammar is a context free grammar.
```
S -> aSb
S -> ab
```
Here S is a nonterminal. This grammar generates strings made of a and b. S is expanded into aSb or expanded into ab.

a and b are terminals. a or b are no longer expanded.

Using this Context free grammar, you can check whether some string matches the grammar.
For example the following sentence matches the grammar above.
```
aaabbb
```
If you apply the grammar above to this sentence, derivation is possible as follows.
```
S -> aSb -> aaSbb -> aaabbb
```

### Syntax tree

You can also express the derivation process above as a tree.
```
S
├── a
├── S
│   ├── a
│   ├── S
│   │   ├── a
│   │   └── b
│   └── b
└── b
```
This tree expresses the derivation that generates the sentence. This tree is called a syntax tree.

### AST

But a syntax tree also includes content the compiler doesn't need, like parentheses or commas.
What you get by abstracting that content and making it into a tree that only holds structural meaning is an abstract syntax tree.

For example, suppose you have a sentence like this,
```python
def f(a: int, b: int) -> int:
    return a + b
```
If you made a syntax tree it would be expressed like this,
```
def
├── f
├── (
├── a
├── :
├── int
├── ,
├── b
├── :
├── int
├── )
├── ->
├── int
├── :
└── return
    ├── a
    ├── +
    └── b
```

Expressed as an AST it looks like this.
```
FunctionDef
├── f
├── arguments
│   ├── a
│   ├── b
│   └── int
├── int
└── Return
    ├── BinOp
    │   ├── a
    │   ├── +
    │   └── b
    └── int
```
Punctuation like `:`, `->`, `(`, `)` in the syntax tree above is not expressed as nodes in the AST, and `def` and `return` appear as `FunctionDef`/`Return` nodes.
A tree that only expresses structure like this is called an AST.

An AST made like this expresses the structure of the code, so interpreting an AST is pretty much the same meaning as interpreting the structure of the code.
